## 1. 规格六宫格（图1 内容）

图1 为 2 行 × 3 列规格网格：图标 + 字段名（灰）+ 值（加粗），六项依次为
CPU、内存、存储、流量、带宽、IP地址。

### 数据事实（已从 data/monitor.db 抽样 400 条确认）

- `ProductView.spec` 已随 DTO 传到前端，仅 `ProductCard` 未展示，无需后端改动。
- spec 键名自带 emoji 前缀，本身就是展示友好格式：
  `💻 CPU`、`🧠 内存`、`💾 存储`、`📊 流量`、`🚀 带宽`、`🌐 IP地址`（343/400）或 `🌐 IP`（56/400）。
- 绝大多数产品恰好 6 项且顺序与图1 一致；约 15% 产品额外含 `🧩 虚拟化`、`🔌 端口`、`📝 备注` 等。

### 方案

- `ProductCard` 在产品名/标签行与价格行之间插入规格网格：CSS grid 3 列 × 2 行，
  每格 = emoji 图标 + 字段名（灰色小字）+ 值（加粗）。
- 字段名由键名剥离 emoji 得到，emoji 直接作彩色图标（与图1 风格一致，零图标资源成本）。
- 取格策略（保证卡片统一大小）：按固定优先级 `CPU → 内存 → 存储 → 流量 → 带宽 → IP地址/IP`
  取满 6 格；不足 6 格用剩余键按原顺序补齐，空位显示 "-"；第 7 项起（虚拟化/端口/备注）
  不占格，规格区 hover Tooltip 展示完整键值。
- 新增纯函数 `pickSpecEntries(spec)` 抽取上述逻辑，配 vitest 单测（优先级、IP 双键名、
  不足 6 格、超 6 格、空值、非字符串值）。

## 2. 卡片统一大小

现状：`Products.tsx` 的 `Row/Col` 网格中卡片高度随内容浮动（名称折行数、有无
promo/地区标签/buyUrl 不同）。

- `Row` 加 `align="stretch"`，`Col` 内 `Card` 高度 100%（宽度本由栅格统一）。
- 内容区行数固定，消除卡片间高度差：
  - 产品名固定 min-height（按最长单行）；
  - 标签行（地区/系列/线路）固定 min-height；
  - 规格区恒 3 列 × 2 行（需求 1 天然固定）；
  - 价格行、footer 行各恒 1 行（无 buyUrl 时购买按钮不渲染但 min-height 占位）。
- 效果：同一行卡片严格等高；行间因内容行数固定自然一致。

## 3. 购买按钮修复（调起默认浏览器）

根因：Tauri WebView 中 `window.open(url, "_blank")` 与 `<a target="_blank">`
没有浏览器上下文，点击无效。

修复：统一改用 `@tauri-apps/plugin-opener` 的 `openUrl()`——JS 包（^2）已在
dependencies，Rust 插件已在 lib.rs 注册，capability `opener:default` 已允许
http/https 外链，仅需改前端调用点：

| 位置 | 现状 | 改法 |
|---|---|---|
| `ProductCard.tsx` 购买按钮 | `window.open(...)` | `openUrl(product.buyUrl)` |
| `Restock.tsx` 历史列表购买链接 | `Typography.Link href target=_blank` | 保留样式，`onClick` 阻止默认 + `openUrl` |
| `About.tsx` GitHub 链接 | 同上（同类失效） | 同上，顺带修复 |

## 4. Windows 通知渠道

现状：告警渠道 `local | telegram | webhook`（`Channel` 枚举 + `dispatch` 三分支 +
Rules 表单 Select + Alerts 页颜色/文案）。

### 后端

- `Cargo.toml` 加 `tauri-plugin-notification = "2"`，`lib.rs` 注册插件。
- `model.rs`：`Channel` 枚举加 `Windows` 变体（`as_str()` 返回 `"windows"`，
  `ALL` 扩为 4）；规则表 `channel` 列存字符串，天然向后兼容，旧数据不受影响。
- 仿既有 `StatusSink` 模式（引擎不感知 Tauri、测试可注入假实现）：
  - `engine.rs` 新增 `Notifier` trait：`fn notify(&self, title: &str, body: &str) -> Result<(), String>`；
  - `CollectCtx` 加 `notifier: Arc<dyn Notifier>` 字段；
  - Tauri 实现 `WindowsNotifier { app: AppHandle }` 放 `commands.rs`（与 `IpcSink` 并列），
    内部 `app.notification().builder().title(..).body(..).show()`；
  - `service.rs` 测试用 no-op 实现。
- `alerts.rs` `dispatch` 加分支：`Channel::Windows` → `ctx.notifier.notify("VPS Monitor", message)`，
  成功记 `"sent"`、失败记 `"failed"` + 错误，沿用既有 `insert_alert` 落库（Alerts 页可见）。
  消息体复用 `build_message`（Windows toast 支持多行文本）。

### 前端

- `types.ts`：`Channel` 联合类型加 `"windows"`。
- `Rules.tsx` 渠道 Select 加选项 "Windows 通知"。
- `Alerts.tsx`：`CHANNEL_COLORS` 加 `windows: "green"`；渠道名走既有 `t('channel.windows')`。
- `zh-CN.json` / `en.json` 加 `channel.windows`（"Windows 通知" / "Windows notification"）。

### 边界与注意点

- 原生通知无需用户配置项，Settings/SummaryView 不动。
- 仅后端 Rust 调用通知插件，不需要 capability 权限条目。
- Windows toast 依赖应用 AUMID 快捷方式：安装版（NSIS）正常；
  `tauri dev` 开发模式下可能不弹，联调验证需以安装包/构建产物为准。
- 通知频率由规则既有 cooldown 机制控制，本设计不做额外限流/分组。
