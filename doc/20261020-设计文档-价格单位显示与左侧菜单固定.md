| # | 需求 | 类型 |

## 1. 价格显示加单位

### 1.1 数据事实（已从代码与 data/monitor.db 验证）

- 单位数据确实有返回：`products` 表有 `unit` 列（`store/mod.rs:54`），采集自源 JSON 的
  `unit` 字段（`monitor/normalize.rs:195`）。本地库 416 条商品全部有值，分布：
  月 240、月付 103、年 57、季 10（季+季付）、半年 3、年付 3。
- `price` 字符串已自带货币符号（`¥36.99`、`C$5.00`、`$9.00`），目标格式即
  `price + "/" + unit` 简单拼接。
- 拼接先例：告警消息 `monitor/alerts.rs:72-79` 已按此拼接，且带两条容错
  （unit 为空不拼、price 已以 unit 结尾不重复拼）。
- 三个页面数据现状不同：

| 页面 | 数据现状 | 结论 |
|---|---|---|
| 库存（Products 卡片） | `ProductView` 前后端均已带 `unit` 字段（`model.rs:243`、`types.ts:85`） | 纯展示遗漏，只改前端 |
| 总览（Dashboard 最近事件表） | `EventView` 缺 unit：`store/events.rs:53` 的 SQL 未查 `p.unit`，DTO（`model.rs:285`）无字段 | 需后端补字段 |
| 补货动态（本地事件列表） | 与总览共用 `EventView`、同一 `list_events` 查询 | 后端补一次，两页受益 |

- 例外：补货动态页下方「官方动态」（source_history）**无法加单位**——源 JSON 的
  history 项只有 time/name/price/buy_url 四个字段（`normalize.rs:212-234`），
  无周期数据，库表亦未存，保持原样。

### 1.2 方案

后端（2 文件）：

- `store/events.rs` `list_events`：SELECT 列表**末尾追加** `p.unit`（追加到末尾使新列
  索引为 16，不动既有 `row.get(0..15)` 索引），`to_view` 闭包补 `unit: row.get(16)?`。
- `model.rs` `EventView`：追加 `pub unit: String`（结构体已是
  `#[serde(rename_all = "camelCase")]`，TS 侧同名 `unit`，无需 rename）。
- 增量字段，无 SQLite schema 变更，旧前端拿到多余字段无影响。

前端（5 文件，其中 1 新增）：

- `types.ts`：`EventView` 加 `unit: string`（文件头注释声明与 Rust 镜像契约，同步修改）。
- 新增 `src/price.ts`：导出纯函数 `priceWithUnit(price, unit)`，三个展示位统一复用。
  逻辑对齐 `alerts.rs` 语义并加展示归一化：
  - unit 为空 → 原样返回 price；
  - unit 非空且 price 非空 → `price + "/" + 去尾付(unit)`；
  - price 为空（调用方回退美元折算价 `$x.xx`）→ 不拼周期，折算参考价不带周期语义；
  - 防御：price 已以 unit 结尾时不重复拼（与 alerts.rs 一致，实际数据未见此形态）。
- `ProductCard.tsx:84`：`price` 变量改走 `priceWithUnit(product.price, product.unit)`
  （`priceUsd` 回退分支不拼单位）。
- `Dashboard.tsx:200-210`：价格列 `priceText` 改走 `priceWithUnit`；变价行
  `${old} → ${new}（priceText）` 中 old/new 为美元折算数值，保持纯数字，仅括号内
  当前价带单位。
- `Restock.tsx:73`：本地事件 `{e.currentPrice}` 改 `priceWithUnit(e.currentPrice, e.unit)`；
  `:94` 官方动态 `h.price` 不动。

### 1.3 决策点：单位显示格式（待确认）

数据中「月」与「月付」并存（240 : 103），「年/年付」「季/季付」同理，直接拼接会出现
`¥36.99/月付`、`¥99/年付`。

- **推荐 A（展示层归一化）**：`priceWithUnit` 内去掉 unit 尾部「付」字，统一显示
  `¥36.99/月`、`¥99/年`、`¥15/季`、`¥50/半年`。仅影响显示，不改存储与告警消息。
- 备选 B（原样拼接）：直接 `price/unit`，实现最简，但同类商品显示格式不统一。

### 1.4 边界与注意点

- 官方动态无单位是源数据限制，不做反向补数据或按商品名猜测周期。
- unit 为中文（月/年/季/半年），英文界面同样显示中文单位——与商品名、regionCn 一致，
  均为源站数据，不做翻译；无新增 i18n key。
- 告警消息（alerts.rs）格式保持现状，不纳入本次统一（如需统一另起小改动）。

## 2. 左侧菜单固定

### 2.1 根因

`App.tsx:87` 外层 `Layout` 仅 `minHeight: 100vh`，`Content` 无独立滚动容器，长页面
（补货动态：100 条本地事件 + 30 条官方动态）撑高整个 document，Sider 随页面一起滚走。
项目无自定义 CSS（仅 antd reset.css），body 即滚动容器，无干扰因素。

### 2.2 方案

`App.tsx` 的 `Sider` 加 sticky 样式，一处改动：

```tsx
<Sider
  theme="dark"
  width={200}
  style={{ position: "sticky", top: 0, height: "100vh", overflowY: "auto" }}
>
```

- 页面滚动时菜单钉在左侧不动；
- 窗口过矮导致菜单自身超高时，菜单内部可滚（`overflowY: auto`）；
- 不引入 fixed 定位的 margin-left 补偿，不调整布局结构。
