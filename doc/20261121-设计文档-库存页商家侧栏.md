# 设计文档：库存页左侧商家筛选栏

日期：2026-11-21 ｜ 状态：已确认（2026-11-28），实施计划见 `doc/20261128-实施计划-库存页商家侧栏.md` ｜ 规模：小改动（纯前端，单页面）

## 意图与为什么

库存页的商家筛选目前是顶部一个多选下拉，看不见全貌、切起来别扭。改为**常驻左侧栏**：
多选商家 + 一键 ALL，每行顺带显示该商家「有货/总数」（ok/total），一眼看全 23 家商家的库存健康度。
交互稿（已确认）：`.superpowers/brainstorm/426-1795228443/content/vendor-sidebar-layout.html`

## 目标

- 库存页内容区左侧新增商家栏（约 224px）：顶部「全部 (ALL)」单选行 + 商家多选列表（复选框 + 名称 + ok/total 计数）。
- 顶部原「商家」多选下拉**移除**，单一筛选入口（用户已确认，避免双入口状态不同步）。
- 商家栏可收起（«/»），收起后保留窄条（竖排「商家筛选」+ 展开按钮），恢复窄窗口卡片列数。
- 商家栏内置搜索小框，前端过滤商家列表本身（不影响商品筛选）。
- ok=0 的商家计数灰显，ok>0 绿显。

## 非目标

- 不改后端/Rust：`productsList` 已支持 `vendors` 数组，ALL = 不传参，现状逻辑直接复用。
- 不动其他页面、不做地区筛选侧栏化、不持久化筛选与收起状态（保持现状：刷新即重置）。
- 不显示商家 logo（外链有防盗链风险，且无本地缓存，`VendorStat.logo` 字段留而不用）。

## 约束

- antd 组件 + 既有 `Products.tsx` 结构；筛选状态 `vendor: string[]` 沿用，空数组即 ALL。
- i18n 双语（zh-CN/en）新增键须过 parity 测试。
- 布局适配：卡片网格改为**按内容区宽度自动排列**——每列至少 264px、最多 4 列；侧栏展开时列数相应减少（卡片不被挤窄），收起后恢复。
  （2026-11-28 修正：原文写“断点不变”。但列数按窗口宽度固定时，展开侧栏只会把卡片挤窄——默认窗口下 291px→212px、窗口宽 1200–1400 时只有 158–208px，规格值会被大量截断，且与布局稿“收起后列数恢复”的演示不符。）

## 备选方案

- **A（选定）：常驻左侧栏 + 可收起**。直观、能显示 ok/total；代价是横向占 224px，用收起补偿。
- B：仅给顶部下拉加 ALL 选项。改动最小，但用户明确要左侧栏，弃。
- C：下拉 + 侧栏双入口。状态同步复杂，用户已同意移除下拉，弃。

## 实现要点（给执行者）

1. `src/pages/Products.tsx`：外层改 flex 布局——左侧 `Card`（商家栏）+ 右侧原内容；`vendor` state 与
   `resetPage` 复用不动；删除顶部商家 `Select`（`Products.tsx:84-99`）。
2. 商家栏：标题「商家」+ 收起按钮（antd `Button` type=text + 左右箭头 icon）；ALL 行点击清空 `vendor`；
   商家行点击 toggle；`ok/total` 用 `vendors`（`vendorsList()`）现成数据上色。
3. 搜索小框过滤 `vendors` 列表（name/key 前端匹配）。
4. i18n 新键（双语）：全部 (ALL)/All (ALL)、搜索商家/Search vendors、收起/Collapse、展开/Expand。
5. 收起状态仅组件内 state，默认展开，不持久化（最简，my call）。
6. 卡片网格：`Row/Col` 换成 CSS Grid，列宽规则 `repeat(auto-fill, minmax(max(264px, calc(25% - 9px)), 1fr))`、间距 12px——`25% - 9px` 是 4 列时每列的宽度，取它与 264px 的较大者，第 5 列永远放不下。

## 验收

- 多选商家过滤生效、计数与分页回第 1 页；ALL 清空恢复全量（416 款档位）。
- 收起/展开不丢已选商家；收起后卡片列数恢复。
- 卡片列数随内容宽度变化：默认窗口（1180 宽）展开 2 列、收起 3 列；任何宽度下卡片不小于约 250px。
- 顶部筛选条移除商家下拉后其余控件排列不乱。
- `pnpm test`（含 i18n parity）、`pnpm build` 通过。
- UI 截图或本地 dev 供用户过目（视觉验证，不以"代码已改"代替）。
