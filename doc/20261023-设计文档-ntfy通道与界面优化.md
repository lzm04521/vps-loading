# 设计文档：ntfy 通道与界面优化（六项）

- 日期：2026-10-23
- 状态：待评审（五项已评审通过，第六项为追加项）
- 范围：vps-loading（Tauri 2 + React + antd）
- 原始清单六项，其中「售罄不显示购买链接」经确认放弃；评审后又追加「库存供应商多选」，本文共覆盖六项。

## 意图与背景

应用目前有 4 个告警通道（本地 / Telegram / Webhook / Windows 通知），设置页是 5 张卡片一竖条，告警记录只读，库存分页固定每页 24 条，数据源里的评测地址（`blog_url`）落库但前端从不展示。本次：

1. 新增 ntfy 推送通道（对接自建 ntfy，参考 `D:/GitHub/CloudServer/handoff/20261023-handoff-ntfy对接方式.md`）。
2. 设置页重做为**左侧分块菜单 + 右侧内容**（用户已选定该形态，备选 Tabs / Collapse 已排除）。
3. 告警记录支持单条删除与清空。
4. 库存页每页条数可选（最大 1000，用户已确认含义）。
5. 库存卡片与事件列表展示评测地址，点击调起默认浏览器。
6. 库存页供应商筛选支持多选（追加项）。

## 目标 / 非目标

**目标**：上述六项全部落地，旧配置文件与旧数据库无需迁移即可继续使用；`cargo test` 与 `pnpm test` 全过。

**非目标**：

- 售罄隐藏购买链接（已放弃）。
- 告警推送消息体追加评测链接（保持消息简短，未要求）。
- 设置页新增「发送测试通知」按钮（各通道均无此功能，不单独为 ntfy 加）。
- 一条规则同时分发多通道（维持一规则一通道现状）。

## 方案取舍（Approaches）

- **设置页布局**：Tabs / Collapse / 左菜单+右内容三选一，用户选定左菜单+右内容。
- **ntfy token 存放**：配置文件 vs Windows 凭据管理器（keyring）。选 keyring，与 Telegram token 同机制（`secrets.rs`），token 不落盘。
- **事件行评测地址来源**：events 表未存历史快照，JOIN 取产品**当前** `blog_url`——与事件行购买链接（`buy_url`）现状语义一致，接受。
- 其余各项实现路径唯一（在现有枚举 / 命令 / 组件上加），无备选方案。

## 一、ntfy 通知通道

### 配置与密钥

- `AppConfig` 新增 `ntfy: NtfyConfig { server_url, topic }`（serde 带 default，旧配置缺键兼容，参照 `AppSettings` 既有测试模式）。
- token 存 keyring：`NTFY_TOKEN_REF = "vpsmonitor:ntfy-token"`（`secrets.rs` 新增常量，复用 save/load/delete）。
- `ConfigInput` 新增 `ntfyServerUrl / ntfyTopic / ntfyToken`，token 沿用「留空不改、空串清除」约定。
- `ConfigView` 新增 `ntfyServerUrl / ntfyTopic / ntfyTokenSet`。
- `SummaryView` 新增 `ntfyConfigured`，总览页通道状态行补一个 Tag（与 Telegram/Webhook 状态并列）。

### 通道接入

- `Channel` 枚举新增 `Ntfy`（`"ntfy"`），`Channel::ALL` 扩为 5 项；`commands.rs::validate_rule` 走 `Channel::parse` 自动放行。
- 旧版本应用读到 `"ntfy"` 会 `parse` 失败回退 local，无迁移负担。
- 发送（`monitor/alerts.rs` 新增 `send_ntfy`）：
  - `POST {server_url 去尾斜杠}/{topic}`，超时 15 秒，同其他通道。
  - Header：`Authorization: Bearer <token>`（ntfy v2.32 仅此一种鉴权可行）；`Title: VPS Monitor`（纯 ASCII，中文不能进 header）；`Priority` 与 `Tags` 按事件类型映射（见下）；正文复用 `build_message` 输出（自带购买链接行）。
  - 成功判定 HTTP 200；错误信息 mask token。
  - server_url / topic / token 任一缺失 → 记 failed 并给明确错误文案（对齐 `send_telegram` 的「未配置」风格）。

**事件类型 → Priority / Tags 映射（我的默认取值）**：

| 事件 | Priority | Tags |
|---|---|---|
| 补货 restock | high | rotating_light |
| 售罄 soldout | default | warning |
| 降价 price_down | high | money_with_wings |
| 涨价 price_up | default | chart_with_upwards_trend |
| 新品 new_product | default | sparkles |

**可测试性**：拆纯函数 `ntfy_request(event_type, cfg, token, message) -> (url, Vec<(header, value)>)` 单测 URL 拼接（含尾斜杠处理）与映射表；`send_ntfy` 只做 IO 薄封装（对齐该文件「纯函数与 IO 分离」的既有注释）。

### UI 接入点

- `Rules.tsx` 通道下拉加 ntfy 选项；`Alerts.tsx` `CHANNEL_COLORS` 补 `ntfy: "geekblue"`。
- i18n：`channel.ntfy`（zh「ntfy 推送」/ en「ntfy Push」）、设置页表单标签若干。
- 设置页通知块新增 ntfy 组：服务地址（placeholder 用通用 `https://ntfy.example.com`）、Topic（placeholder `vps-loading`）、Token（Password 输入，交互同 Telegram token）。

### token 获取流程（运维侧，不在代码内）

用户在广州机按 handoff 执行 `docker exec -e NTFY_CONFIG_FILE=/etc/ntfy.yml ntfy ntfy token add --label="vps-loading" lzm` 新建专用 token（不复用现有 token），从命令输出取值填入设置页；topic 建议 `vps-loading`。token 值不进代码库与文档。

## 二、设置页重做（左侧分块菜单 + 右侧内容）

### 分块（4 块，由现有 5 张卡片归并）

1. **采集**：数据源地址、采集间隔（现「采集」卡片原样）。
2. **通知**：Telegram（token 状态 + 输入 + chat_id）、Webhook URL、ntfy 三组，**一个保存按钮**单次 `configUpdate` 提交。
3. **应用**：开机自启、语言、日志级别（现「应用」卡片原样）。
4. **数据管理**：配置/数据库路径展示、打开日志目录（现「路径」卡片）+ 旧版数据导入（现「旧版导入」卡片）。

### 布局与实现

- 左侧 antd `Menu`（vertical，约 180px，`position: sticky` 长页滚动保持可见——与主菜单固定做法一致）；右侧内容区渲染当前选中块。
- 选中块存组件 state，默认进「采集」。
- 小屏（< md）：菜单退化为内容区上方的横向 `Menu`（horizontal），不挤占横向空间。
- 文件结构：`Settings.tsx` 拆为 `src/pages/settings/` 目录：`index.tsx`（布局骨架 + 菜单）与 `CollectSection.tsx / NotifySection.tsx / AppSection.tsx / DataSection.tsx`。现状单文件 284 行，加入 ntfy 后通知块显著变大，拆分避免单文件超 500 行。
- 各块保留各自 Form + 保存按钮与独立 loading 态，逻辑从现文件平移，不做行为变更。

## 三、告警记录删除与清空

- `store/alerts.rs` 新增：`delete_alert(id) -> Result<bool>`、`clear_alerts() -> Result<usize>`（返回删除条数）。
- `commands.rs` 新增 `alert_delete(id)`（未命中返回 `ALERT_NOT_FOUND`）与 `alerts_clear()`；`lib.rs` 注册，`api/ipc.ts` 加调用，`types.ts` 无新类型。
- `Alerts.tsx`：操作列在「购买」旁加删除链接（Popconfirm 确认）；Card 标题右侧加「清空」按钮（Popconfirm + danger）；成功后刷新列表并提示清空条数。
- **已知行为（用户已接受）**：告警记录参与冷却期判断（`recent_alert_exists`），删除冷却期内记录后，同一规则+产品若再次命中会重新推送，不做额外保护。
- i18n：删除 / 清空 / 确认文案、成功提示。

## 四、库存页每页条数可选

- 默认 24 不变；antd `Pagination` 开 `showSizeChanger`，`pageSizeOptions = [24, 48, 96, 200, 500, 1000]`。
  - 区间取值理由：24 为现默认（xl 屏 4 列×6 行）；48 / 96 逐级翻倍适合常规浏览；200 / 500 / 1000 覆盖全量一屏粗筛。上限 1000 按需求，后端 `query_products` limit clamp 已到 2000，无需动。
- 切换每页条数时重置回第 1 页；`total` 概念不变。

## 五、评测地址展示（库存 / 事件）

- `ProductCard.tsx`：底部操作行「购买」旁加「评测」链接（`blogUrl` 非空才显示），`openExternal` 打开默认浏览器。
- `EventView`（Rust `model.rs` + 前端 `types.ts` 镜像）新增 `blogUrl`；`store/events.rs::list_events` SELECT 追加 `p.blog_url` 列（含测试断言）。
- `Restock.tsx`（补货动态列表）与 `Dashboard.tsx`（最近事件表格操作列）在「购买」旁加「评测」链接。
- 告警记录页不加（需求只提库存/事件）。
- i18n：`products.review`（zh「评测」/ en「Review」）。

## 六、库存供应商多选

- 后端：`ProductQuery.vendor: Option<String>` 改为 `vendors: Option<Vec<String>>`（IPC 前后端同包发布，原地替换不留旧字段）；`store/catalog.rs::build_where` 过滤空串后非空列表拼 `p.vendor_key IN (?, …)`，空列表 / None 不加条件（= 全部商家）。地区筛选维持单选不动。
- 前端 `Products.tsx`：供应商 `Select` 改 `mode="multiple"` + `allowClear` + `maxTagCount="responsive"`，去掉「全部商家」固定项（多选语义下清空即全部）；选中集合变化时重置回第 1 页；查询参数传 `vendors`（空数组传 null）。
- `types.ts` 镜像 `vendors: string[] | null`。无新增 i18n 键。

- Rust：`cargo test`（新增 ntfy_request 映射 / URL 拼接、delete/clear、events blog_url 断言；既有测试不回归）。
- 前端：`pnpm test` + `pnpm build`（tsc 全量类型检查）。
- UI：dev 起本地界面供过目设置页新布局、库存每页条数、评测/删除入口；ntfy 通道由用户建 token 后在设置页配置，手动触发一次采集验证真机推送。
